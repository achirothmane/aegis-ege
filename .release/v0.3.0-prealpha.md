# Aegis-EGE v0.3.0-prealpha

Aegis-EGE is an experimental evidence-gated execution layer for AI agents and high-consequence automation.

This release packages the project around the product-level Aegis-EGE protocol rather than the earlier StateLatch-only framing.

The first supported real action remains deliberately narrow:

```text
kubernetes.node_drain
```

## What changed since v0.2.0-prealpha

### Generic execution-intent gate

Aegis-EGE now exposes a product-level control path above StateLatch:

```text
Execution Intent
→ Evidence
→ ALLOW / BLOCK / ESCALATE
→ signed Permit
→ live revalidation
→ guarded mutation
→ outcome verification
```

### Signed Evidence Manifest + execution permit

An ALLOW decision can produce:

- Evidence Manifest v0alpha2;
- Ed25519-signed execution permit;
- exact intent/action/target/state binding;
- evidence-manifest digest binding;
- deterministic plan binding;
- short expiry.

Permit verification happens before mutation.

### Evidence Producer / Execution Adapter split

Evidence generation and mutation execution are separate responsibilities.

```text
Evidence Producer
→ justifies action

Execution Adapter
→ executes only after a valid permit
```

### Evidence composition

Aegis-EGE can require multiple named evidence sources and distinct declared trust domains before permit minting.

The manifest binds the composed source set into the signed permit.

### First real external contributor: Prometheus

Optional Prometheus node-health evidence can now participate in node-drain decisions.

When configured:

```text
StateLatch / Kubernetes
+ Prometheus node health
+ 2 declared trust domains
→ permit eligible
```

Contradiction:

```text
Kubernetes: healthy
Prometheus: unhealthy
→ BLOCK / EVIDENCE_CONTRADICTED
→ no permit
```

Unavailable required Prometheus evidence fails closed.

### Incremental-value falsification

A new KinD test proves that Prometheus can veto an action the Kubernetes-only path would otherwise authorize.

For the same node and same drain intent:

```text
Kubernetes-only
→ ALLOW
→ permit
```

but:

```text
Kubernetes + contradictory Prometheus
→ BLOCK
→ no permit
→ no mutation
```

This is a narrow, reproducible safety claim—not a claim that every Prometheus deployment is automatically operationally independent.

## Existing safety foundation retained

StateLatch still provides the assurance engine for the current node-drain path, including:

- continuous state invalidation;
- bounded read-only evidence acquisition;
- contradiction reconciliation;
- transitive assumptions;
- action-sensitive temporal validity;
- server-side dry-run;
- deterministic plan binding;
- short-lived state-bound authorization;
- final and in-flight revalidation;
- Kubernetes Lease execution locking;
- partial-failure checkpoints and recovery;
- durable replay rejection;
- signed hash-chained execution journal;
- mTLS PREPARE/EXECUTE authorization;
- shared Kubernetes HA state;
- external anti-rollback/key-custody boundaries;
- postflight outcome verification.

## Safety posture

Real Kubernetes mutations remain disabled by default.

The experimental mutation path must be explicitly enabled.

This is a **pre-alpha research/prototype release**, not a production-ready replacement for `kubectl drain`.

## Adoption gate

The technical surface is now ahead of adoption.

Major new product-surface expansion remains gated on external usage evidence in `ADOPTION.md`.

The intended next step is to get real users to run the existing path, report friction, and show whether this safety difference matters in practice.
